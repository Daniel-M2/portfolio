Background

Crypto adoption is outrunning crypto security

Global crypto adoption keeps growing, but so does the cybersecurity risk that comes with it. In 2024 alone there were 303 hacking cases totaling $2.2 billion in stolen funds. Earlier that year, Bybit suffered a single theft of roughly 400,000 ETH (~$1.4 billion) at the hands of North Korean hackers — the largest single theft in crypto history.

Dataset

Wallet-level transaction behavior

The dataset captures Ethereum wallet activity — sending/receiving frequency, unique counterparties, ETH balances, and ERC-20 token transaction history — labeled for known fraudulent versus legitimate addresses.

Methodology

Five models, one winner

Five supervised classifiers were trained and compared on the same wallet-behavior features — KNN, SVM, Decision Tree, Random Forest, and XGBoost — to determine which handled this fraud-classification task best.

Results

What a fraudulent wallet looks like

Typical wallet behavior

10,178 ETHAverage cumulative ETH sent per wallet (~$30M)
11,658 ETHAverage cumulative ETH received per wallet (~$35M)
  • Users send crypto every 3–4 days on average and receive every 5–6 days
  • Each wallet typically receives from ~30 unique addresses and sends to ~26 unique addresses
  • Only a small fraction of users interact directly with smart contracts (voting, token swaps, DeFi, NFTs, DEX trades)

Token exposure

EOS, OmiseGO, and Golem are the three most popular tokens by transaction volume — but Tronix and OmiseGO top the list of tokens most frequently flagged in fraudulent transactions.

Best-performing model

XGBoost outperformed the other four models, delivering both the highest recall score and the lowest standard deviation across validation folds — the combination that matters most for flagging fraud without excessive false negatives.

Where the model is strong vs. where it struggles

Flags accuratelyStruggles with
New wallets (<1 month old) with received-transaction gaps ≤1 hour and 4–12× transaction counts, sending to 1–2 addresses but receiving from 2–7, average value <10 ETH, near-zero balance (0.0005–0.002 ETH), and mostly unpopular/unknown ERC-20 tokens Wallets with higher transaction value (≥12 ETH), higher trade frequency, newer wallets under 3 months, and activity spread across unfamiliar or unnamed ERC-20 tokens — the model tends to overfit toward the dominant, well-represented patterns in the data

Conclusions

A useful first filter, not a final verdict

  • The model reliably flags newer, low-activity wallets dealing mostly in lesser-known tokens, but struggles with newer wallets showing higher value or more varied activity
  • It's limited to predicting fraud based on wallet address behavior rather than the underlying transaction hash itself
  • Many token names used as features may lose relevance over time, since altcoins frequently fall out of use between market cycles

Business Recommendations

Where this plugs into exchange security

Raise token-listing security thresholds

Collaborate with Web3 security services like CertiK on both centralized and decentralized exchange platforms.

Delist suspicious tokens promptly

Remove tokens shown to be prone to fraudulent transaction patterns as soon as they're flagged.

Permanently ban fraudulent wallet addresses

Once an address is confirmed fraudulent, block it from re-entering the platform under the same identity.

Limit device/IP-based wallet creation

Prevent flagged users from simply spinning up a new wallet address to continue fraudulent activity.

Add a pre-transaction wallet check

Give CEX/DEX users a simple, user-friendly wallet address risk check before they confirm a transaction.
